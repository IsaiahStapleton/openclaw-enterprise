# Feature Spec: GitHub Actions integration and test coverage for Enterprise

**Date:** 2026-09-04
**Status:** Implementation in progress — PR coverage verified; specialized live acceptance remains
**Owner:** Enterprise maintainers (suite coverage and cleanup); repository administrators (Actions policy and protected environments)

## Problem and Decision

Start with PR-safe local and PostgreSQL checks, then add disposable image/Kubernetes checks and a protected real-model lane. Extend those same two workflows to complete the broader test inventory once specialized resources are ready. Preserve the Node test runner, existing Drivers and test contracts. A selected missing prerequisite or skipped expected case must fail its lane.

The [refreshed report](reports/openclaw-testing-infrastructure.md) was completed first and owns upstream evidence, source mismatches and the full inventory. This plan targets reviewed main [`1233e13`](https://github.com/openclaw/openclaw-enterprise/commit/1233e13aa6e1a2e4f502fa5febf06f5531c19f2c): 19 conformance, 37 integration and two browser files. Canonical authoring HEAD `f0b17b7` additionally contains three logging files and new gated log assertions. Inventory the eventual implementation SHA; do not change branches or restore historical `setup-*` suites to meet an old count.

The user removed the workflow prohibition from [AGENTS.md](../AGENTS.md) and authorized implementation on September 4. GitHub accepted the workflow push in [PR #23](https://github.com/openclaw/openclaw-enterprise/pull/23). This proposal follows [the platform design](../docs/design.md) and changes test orchestration, not application architecture.

## Scope

**Included:** PR-safe integration, protected provider-backed execution, current conformance/browser coverage, skip accounting, disposable setup/cleanup, bounded failure evidence, and repairs needed to exercise supported tests. The September 4 continuation also authorizes runtime/API compatibility repairs for routing identity scopes, dedicated Codex sandbox execution, outgoing image visibility, and OpenShell packet filtering, while preserving authorization and isolation. The complete inventory remains the target; partial delivery must name its remaining lanes.

**Excluded:** production/customer resources; live credentialed execution without the approved dedicated resources and budget below; unrelated product API/auth changes; Vitest migration; wholesale upstream CI import; native-platform matrices and timing/sharding infrastructure without measured need.

## Contract

### Workflow and trust boundary

| Proposed workflow                        | Trigger and revision                                                                                                                                                                                                      | Jobs and completion claim                                                                                                                                                                                                                                     |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.github/workflows/ci.yml`               | Every PR, main push and manual run; add `merge_group` if the repository uses merge queue. No initial path or draft filters.                                                                                               | Initially `checks-baseline`, `postgres`, `ci-required`; later add `images-packaging` and `k3d-fixture-configuration`. `ci-required` names exactly the delivered PR-safe coverage, never all live integrations.                                                |
| `.github/workflows/full-integration.yml` | Manual dispatch **from main only** initially. Resolve the dispatched immutable main SHA once; all checkout/build/test jobs use it. No arbitrary target-ref input. Enable nightly only after resource and budget approval. | Initially `docker-model` and aggregate `runtime-integration`; then `k3d-model`, routing, production TUI and specialized jobs below. Add `full-test-suite` only once all inventory lanes, including PR-safe lanes rerun at the same SHA, are wired and proven. |

Use ephemeral GitHub-hosted Ubuntu 24.04 x64 runners, `contents: read`, SHA-pinned actions, `persist-credentials: false`, and no external secrets in PR jobs. Install Node 24.15+ and manifest-pinned pnpm (currently 11.15.1), then use a frozen lockfile. PR-safe means no privileged external credential: Docker/k3d still has authority over its disposable runner. Verify required packages and image pulls work without private registry credentials before designating a lane PR-safe.

Protect credentialed jobs with explicit environments restricted to main, required reviewers, and no self-approval/bypass where supported. Approval must identify `github.sha`; check out that exact SHA, never freshly resolved moving main. Branch/ref environment rules alone do not validate a custom checkout target, hence the absence of a freeform target input. A rerun at another SHA needs new review. Do not execute PR code through `pull_request_target`, inherited secrets, persistent credential-bearing runners or promoted PR artifacts. [GitHub environment controls](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments), [secure use](https://docs.github.com/en/actions/reference/security/secure-use).

Ordinary `pull_request` jobs may restore and save the pnpm store using lockfile/OS/Node/pnpm keys; GitHub scopes their writes to the PR merge ref. Trusted main jobs save in main scope. Protected main jobs must not consume PR artifacts or externally promoted PR caches. Protected jobs use only their own trusted builds/artifacts. Initially rebuild images in the owning job; introduce build-once artifact fanout when two consumers need the same image. Record source SHA, architecture and immutable image digest; never treat a cache hit as test evidence.

### Coverage and failure contract

Add one small Enterprise-owned suite map (`scripts/ci/test-suites.json`) and runner (`scripts/ci/run-tests.mjs`). The map assigns discovered `tests/{conformance,integration,browser}/*.test.mjs` files and gated scenario names to their invocations, required inputs and permitted counterpart skips. It also records planned lanes until delivered, so staged CI cannot imply complete coverage. It is not another test implementation or a generic planner.

The runner validates prerequisites before execution, preserves Node's exit status, and checks machine-readable Node results for expected named cases, failures and unexpected skips. Dynamic cases use emitted test results, not counts of source `test()` calls. Zero expected cases, missing result output, cancellation, timeout, removed/renamed cases or unmapped new files fail validation. Scoped name filters for routing/timeout must have explicit expected-case lists. A permitted counterpart skip counts only when its owning lane ran successfully within a full-suite run.

Every aggregate uses `always()` and checks the fixed expected job set for that workflow revision plus suite results. Selected skipped/absent/failed/cancelled jobs or missing artifacts fail the aggregate; no blanket `continue-on-error` or advisory pass conversion. `runtime-integration` proves only its delivered model lanes. `full-test-suite` additionally requires every discovered file and gated scenario at one SHA; unavailable specialized resources remain incomplete, never a green all-tests result. This adopts [upstream's selected-job rule](reports/openclaw-testing-infrastructure.md#how-openclaw-runs-tests) and extends it to actual test execution.

### Disposable state, images and secrets

- **Database owner:** the job creates its own Compose project/volume and PostgreSQL databases. Reuse [compose.postgres.yaml](../compose.postgres.yaml) and [role initialization](../migrations/init-local.sql). Migrate as `occ_migrator`, unset its URL before tests, and test as `occ_app`. Use separate fresh DBs for auth-account/platform-state empty Installation proofs and production wireup. Set `OCC_BOOTSTRAP_FAILURE_DATABASE_URL` to exclusive loopback `openclaw_failures_*` and its matching `OCC_BOOTSTRAP_FAILURE_MIGRATION_DATABASE_URL`; set `OCC_PRODUCTION_WIREUP_DATABASE_URL` separately. Never share a database across concurrent files. [DB admission](reports/openclaw-testing-infrastructure.md#gaps-ci-configuration-alone-cannot-fix).
- **Cluster owner:** each k3d job uses a unique run/job suffix, explicit loopback kubeconfig/context and `--kubeconfig-update-default=false --kubeconfig-switch-context=false`. Use dedicated `openclaw_k8s_*` DBs. Prove NetworkPolicy allow/deny behavior, import local image tags, and register exact digest refs inside k3s. Existing helpers mutate local-path storage configuration; run only on the owned disposable cluster. Routing additionally installs pinned reviewed controllers and creates its own CA; never reuse a company CA private key.
- **Image producer:** build the existing controller Dockerfile with `--target runtime --build-arg NODE_BASE_IMAGE=<approved-node24-digest>` and the existing `deploy/runtime/Dockerfile`. Retain current runtime package pins pending a separate change. For production TUI set `OCC_TEST_PRODUCTION_CONTROLLER_IMAGE`, `OCC_TEST_KUBERNETES_RUNTIME_IMAGE`, `OCC_TEST_PRODUCTION_POSTGRES_IMAGE`, `OCC_TEST_PRODUCTION_NODE_IMAGE`. Export/load artifacts only when needed; verify all source/digest/architecture metadata and do not publish images solely to test them.
- **Credential owner:** model jobs use proposed environment `integration-model`; provider, Slack and OpenShell jobs get separate protected environments and only their explicit secrets. Keep admin/model/token files mode 0600 outside artifacts. Preserve existing model-key placement: combined embedded runtime or dedicated Codex Pod, never a separate gateway/controller/fixture. Envoy's test CA key and generated service-account credentials are also sensitive. Serialization per shared test channel/workspace prevents cross-run interference.
- **Cleanup owner:** preserve existing test teardown and add a job-level `always()` sweep of only run-owned Compose resources, cluster, DBs, processes, credential files and temporary external account. Disable KEEP/debug-retention flags in CI. Fail/report cleanup errors with sanitized resource IDs. Abrupt runner loss can prevent teardown: ephemeral runner destruction handles local state, while the test-resource owner reconciles surviving provider accounts and Slack test messages by recorded IDs under an approved retention policy before retry. A hard kill cannot be treated as verified cleanup.

Keep sanitized test names/results, source SHA, tool versions, image digests, model, durations and cleanup status for seven days initially. Save focused failure diagnostics even when tests fail; exclude raw kubeconfigs, bootstrap credentials, state directories, model keys, CA keys and unfiltered container logs. Browser screenshots can contain test data; use only synthetic accounts and the same retention policy.

### Cost and runner limits

Start with one protected run at a time; do not auto-cancel it after external resources exist. Cancel superseded PR runs on ephemeral runners. Suggested initial **budgets to validate**, not measured durations: baseline/Postgres 20 minutes each; images/fixture 40 minutes each; Docker 35 minutes; ordinary k3d model 60 minutes (its cases allow 20 + 15 + 8 minutes); routing 30; production TUI 45; Slack/OpenShell 30; provider 20; helper timeout 10. Reserve teardown headroom and use `fail-fast: false` when independent lanes become a matrix.

Measure cold setup time, Docker disk/memory, image artifact size and provider token spend in the first authorized runs. A dedicated test model project must have an approved spend cap and model allowlist; the job records actual usage where available. Dollar forecasts and specialized runner sizing remain unverified. Enable nightly only after owners accept measured cost, quota and cleanup results; keep manual execution if full-suite resources are unavailable.
